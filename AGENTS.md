# AGENTS.md — инструкция для агентов, работающих с этим проектом

Прочитай целиком перед первой правкой. Как пользоваться — в [README.md](README.md), как устроены шаги — в [docs/development.md](docs/development.md). Этот файл — цели, порядок работы, правила, инструменты и проект ещё не сделанных частей.

Если рядом есть `AGENTS.local.md` — прочитай и его: там правила конкретной машины и её владельца (окружение, пути, общение); при расхождении он важнее. Настройки машины — в `config.local.yaml`, он подхватывается автоматически. Оба файла в репозиторий не попадают.

## Что это

Конвейер `rupipe`: из MKV с многоканальным оригиналом и русской стереодорожкой делает русскую E-AC3 5.1 (1024k) и добавляет её в копию MKV первой дорожкой по умолчанию.

Обычный запрос — собрать **весь сезон**. Главный критерий — субъективное качество; английские голоса допустимо оставлять фоном, ухудшать эффекты, музыку и сцену нельзя.

Основной случай: **плохой стерео-закадр** уровня веб-релизов (AC3/AAC 2.0, 128-384 кбит/с) поверх хорошего оригинала в том же MKV. Типичный оригинал — WEB-DL Apple/Amazon/Netflix/Disney+: E-AC3 5.1 (часто JOC/Atmos), 48 кГц, 576-768 кбит/с. Это поддерживается полностью. Дубляж 2.0 бывает редко, ещё не реализован — делать, когда пользователь принесёт материал. Готовые многоканальные миксы с вшитым голосом без оригинала — не задача проекта.

## Главное правило: каждый файл проверяется, ничего не угадывается

Релизы собирают разные люди как попало. Единого правила нет ни для чего: номера, порядок и названия дорожек меняются от релиза к релизу и даже от серии к серии; теги языка бывают неверными (русская озвучка с тегом eng) и разные утилиты читают их по-разному; в какой-то серии дорожки может не быть; русская дорожка бывает склеена из кусков с разными сдвигами; студии озвучки по-разному сводят голос и приглушают оригинал. Поэтому:

- **Не опираться на примеры из прошлых файлов** — ни на номера дорожек, ни на сдвиги, ни на уровни. Всё измеряется заново для каждого файла.
- **Какую русскую дорожку брать, решает пользователь (оператор).** Если он её не назвал — показать `pipeline plan` и спросить. Если в разных сериях разный состав или названия — показать это и спросить по каждой расходящейся серии. Не брать «первую русскую» и не подставлять выбор молча, чтобы конвейер не остановился. Не называть вариант «очевидным» по метке языка — метки часто неверны, а нужную студию знает пользователь.
- **Сначала план, потом работа.** Ничего не обрабатывать, пока план по всем файлам не согласован с пользователем.
- **После сборки — проверить сводку по каждой серии** и сказать пользователю о всём необычном (много кусков синхронизации, `FLAGGED`, слабое вычитание, срабатывания лимитера, упавшие файлы).
- **Звук оценивает пользователь на слух.** На новом сериале или новой студии озвучки сначала собрать первую серию и нарезать фрагменты, и только после «ок» — весь сезон.

## Порядок работы с сезоном (или файлом)

1. **План.** `uv run pipeline plan <папка сезона>` — по каждой серии все аудиодорожки, что выбрано и где нужен выбор. Ничего не обрабатывает. Показать пользователю, спросить, какая озвучка нужна.
2. **Выбор.** Обычно хватает части названия: `--russian "<часть названия>"` (одна на весь сезон). Если в какой-то серии иначе — `--track-for "<часть имени файла>=<номер или часть названия>"` (или `=original:<...>` для оригинала), можно несколько. Повторить `plan` с выбором и убедиться, что все серии разрешены и выбраны те самые дорожки (кодек, каналы, название совпадают по сезону).
3. **Пробная серия.** `uv run pipeline run <файл первой серии> --russian ...`, затем `uv run pipeline fragments <файл> --count 3` (и `--at HH:MM:SS` для подозрительных мест, например стыков кусков синхронизации). Для новой студии озвучки собирать пробную серию сразу с альтернативами громкости голоса (отдельный `--config` с `mix.variants`, см. README), чтобы пользователь сравнил дорожки в одном фрагменте. Отдать фрагменты, дождаться оценки; по ней при необходимости поправить `mix.target_audible` и пересобрать `--from mix`.
4. **Сезон.** `uv run pipeline run <папка> --russian ... [--track-for ...]`. В конце `run` печатает `SUMMARY` по каждой серии — разобрать её и доложить.
5. **Результат** — в `output_dir`: `<имя>.rus51.mkv` на каждую серию.

## Инварианты — не ломать

- **Ни одна исходная дорожка не удаляется и не меняется** — ни видео, ни аудио, ни субтитры. Новая дорожка добавляется первой среди аудио и ставится по умолчанию; у исходных аудиодорожек снимается только флаг default. (Фрагменты для прослушивания — исключение: в них только нужные для сравнения дорожки.)
- Входной файл не модифицируется никогда; результат — новый файл `<имя>.rus51.mkv` в `output_dir`.
- Каналы, кроме изменяемых (по умолчанию только FC), — декодированный оригинал без обработки.
- Выход только E-AC3 5.1, 1024k: это надёжно проходит passthrough на ресиверы и саундбары с медиаплееров. Раскладка и dialnorm — как у оригинала.
- Знак смещения: `lag = L` значит, что русский сэмпл `j` звучит вместе с сэмплом оригинала `j + L`.
- Приоритет — сохранность эффектов и музыки; остатки английского допустимы.

## Инструменты

```bash
uv run pipeline doctor                                                 # проверка окружения: пакеты, утилиты, место
uv run pipeline plan <файл|папка> [--russian X] [--track-for NAME=X]   # план, ничего не обрабатывает; код 2 = нужен выбор
uv run pipeline run  <файл|папка> --russian X [--track-for NAME=X]     # весь конвейер с возобновлением; в конце SUMMARY
uv run pipeline run  <файл> --from mix                                 # переделать с шага (после правки конфига)
uv run pipeline fragments <файл> [--count 3] [--at HH:MM:SS]            # сцены для прослушивания из готового файла
uv run pytest                                                          # тесты
uv run python tools/build_skill.py                                     # собрать переносимый скилл в dist/
```

Глобальная опция `--out <папка>` (перед командой) задаёт, куда писать результат, `work/` и фрагменты; без неё — пути из конфига, а пустые значения там означают `rupipe-out` рядом со входом.

`X` — номер дорожки (индекс ffprobe, как в `plan`) или часть названия; если частью названия подходят несколько дорожек, берётся та, чьё название совпадает целиком, иначе конвейер спросит. `run` сначала печатает план и при неоднозначном выборе ничего не обрабатывает (код 2). Шаги: `analyze → decode → sync → voice → mix → encode → mux`. Состояние в `work/<имя>/manifest.json`; готовые шаги пропускаются; изменение входного файла или выбранных дорожек начинает файл заново.

Что смотреть в `SUMMARY` и логе:

- `sync N segment(s)` — сколько кусков с разным сдвигом нашлось в русской дорожке. Несколько кусков — нормально для склеенных озвучек, но стыки стоит дать послушать (`fragments --at`). `FLAGGED` — кусков слишком много (похоже на плавный дрейф) или нет уверенных замеров: доложить.
- `leak ... worst` — насколько хорошо оригинал вычитается из русской дорожки в полосе голоса (чем ниже, тем чище голос; около −15 дБ и ниже — хорошо, около −5 дБ и выше — плохо: проверить синхронизацию и выбор дорожек).
- `studio ducking` — насколько студия сама приглушает оригинал под голосом; конвейер повторяет это в центре.
- `voice audible N% (studio M%)` — разборчивость русского голоса в итоге и в балансе самой студии (см. «Настройки звука»); затем поправка к студийному балансу и голос над центром в дБ. Предупреждение «target audibility not reached» (поправка упёрлась в `voice_db_max`) — повод сказать пользователю: микс очень плотный или голос тихий.
- `limited` — сколько сэмплов лимитер подрезал в изменённых каналах. Десятки тысяч на серию на слух не замечались; сотни тысяч — повод дать пользователю послушать громкие фразы.

## Устройство кода (`rupipe/`)

| модуль | шаг | суть |
|--------|-----|------|
| `probe.py` | analyze | ffprobe; dialnorm из заголовка кадра AC3/E-AC3 (ffprobe его не показывает); выбор дорожек без угадывания (`TrackChoiceNeeded`) |
| `decode.py` | decode | ffmpeg → float32 48 кГц, файл на канал; **`-drc_scale 0` обязателен** (иначе декодер сжимает динамику) |
| `sync.py` | sync | плотный GCC-PHAT по всему файлу, куски с постоянным сдвигом и их границы, дробный сдвиг каждого куска |
| `voice.py` | voice | выделение голоса эталонным вычитанием (см. ниже) |
| `audibility.py` | mix | разборчивость голоса в миксе (доля слышимых клеток речи) и подбор громкости голоса под цель |
| `mix.py` | mix | варианты из `mix.variants`: голос в FC, даккинг, пиковый лимитер |
| `export.py` | encode, mux | ffmpeg eac3 1024k с dialnorm оригинала; mkvmerge в копию входа; `track_map` — где какая исходная дорожка в результате |
| `scenes.py` | fragments | подбор сцен по громкости/LFE/речи, нарезка mkvmerge |
| `stft.py` | — | STFT sqrt-Hann, hop = n_fft/4, точное восстановление |
| `cli.py` | — | команды, план, выбор дорожек по файлам (`tracks_for`), сводка |
| `manifest.py`, `config.py`, `tools.py` | — | возобновление, конфиг, запуск внешних утилит |

### Как выделяется голос (voice.py)

Русская дорожка моделируется как `g(t, полоса) · H(f) · оригинал + голос`. `H` — комплексная матрица даунмикса студии (каналы оригинала без LFE → L, R), МНК по всему файлу; комплексность заодно поглощает остаточную дробную задержку. `g` — медленное усиление студии по 14 полосам (её автоматизация громкости и приглушение). Остаток = голос + шум кодека; утечка подавляется спектральной маской. Затем VAD, гейт между фразами, пересчёт голоса в масштаб центра делением на коэффициент FC→L/R, чтобы сохранить студийный баланс голос/оригинал; `mix.variants.*.voice_db` сдвигает его. **Голос не берётся сепаратором и стерео не сводится в моно целиком.** Качество вычитания упирается в точность синхронизации: ошибка в несколько сэмплов убивает вычитание на верхах — поэтому синхронизация кусочная и дробная.

## Настройки звука по умолчанию

- Громкость голоса **подбирается по разборчивости, а не фиксированной поправкой.** Ни поправка к студийному балансу, ни «столько-то дБ над центром» не универсальны: студии сводят голос от ~5 до ~15 дБ над оригинальным центром, а плотный микс (музыка, окружение по бокам и в тылах) маскирует голос сильнее, чем разреженный. Мера (`audibility.py`) — доля частотно-временных клеток речи, где русский голос минимум на 3 дБ громче всего, что слышит зритель; `voice_db: auto` ставит самый тихий голос, при котором она достигает `mix.target_audible`.
- Калибровка на слух (саундбар, две разные студии озвучки): 88-90% — нравится, 79-86% — «английский забивает русский», 92-95% — «голос слишком громкий»; цель 0,89. Мера предсказала выбор пользователя на второй студии до того, как он его назвал. Если пользователь сменит систему или на новой студии скажет «громко/тихо» — менять `target_audible`, а не подстраивать поправку под одну студию. На новой студии можно собрать первую серию с альтернативами (`louder`/`quieter`/`studio`, через отдельный `--config`, см. README).
- Когда пользователь оценивает варианты на слух, сначала посчитать и назвать свой прогноз по мере, потом спросить его выбор — так проверяется, что мера работает.

## Грабли, на которые уже наступили

- `mkvmerge -J` выводит JSON с UTF-8 BOM — читать `utf-8-sig`.
- mkvmerge возвращает код 1 при предупреждениях — это не ошибка (`tools.run(..., ok_codes=(0, 1))`).
- Консоль Windows не UTF-8: в CLI `sys.stdout.reconfigure(encoding="utf-8")`; в разовых скриптах — `PYTHONIOENCODING=utf-8`.
- numpy 2: `ndarray.ptp()` удалён, нужно `np.ptp(x)`.
- Не делать в Python-цикле по частотным бинам индексирование больших массивов — векторизовать через `einsum` (разница — минуты против секунд).
- В Python-строках с путями Windows не писать `\b`, `\t` и т. п. без raw-строк: однажды `\b` превратился в символ backspace в документе.
- Правки файлов через `python - <<'EOF'` в Bash-инструменте ненадёжны: обратные слэши (`\n`) внутри heredoc искажаются, и замены молча не совпадают. Для правок кода и документов — инструменты Edit/Write.
- Теги языка дорожек ненадёжны и у разных утилит различаются (ffprobe и mkvmerge могут видеть у одной дорожки eng и rus). Дорожки находить по номеру/позиции (`track_map` из шага mux), не по тегам.
- Сдвиг из контейнера (`start_time`) почти всегда неточен на единицы-десятки миллисекунд; уточнение синхронизации обязательно.

## Скилл для передачи другим

`skill/` — исходники переносимого Agent Skill `russian-voiceover-51` (для людей с любым агентом, в том числе на слабой модели). `tools/build_skill.py` собирает из `skill/`, `rupipe/` и `config.yaml` папку `dist/russian-voiceover-51/` и zip, проверяя правила формата (agentskills.io) и то же, что `tools/check_public.py`.

- Код у проекта и скилла общий: правишь `rupipe/` — пересобери скилл. Меняешь команды, опции, вывод SUMMARY или настройки — обнови и `skill/SKILL.md` / `skill/references/*.md`.
- Тексты скилла — на английском и простым языком: их должна понимать слабая модель. Агенту там велено говорить с пользователем на его языке. `skill/README.ru.md` — для человека.
- Частные правила конкретной машины (пути, сеть, оборудование) в скилл и в репозиторий не пишутся: им место в `AGENTS.local.md` и `config.local.yaml`.
- Проверка скилла — дать его агенту на слабой модели (Haiku) с реальной задачей: с неоднозначными дорожками он должен остановиться и спросить, с выбранной — довести до конца и отчитаться по SUMMARY.

## Тестовый материал

- Модульные тесты (`tests/`) синтетические, реальных записей в репозитории нет и быть не должно — это чужой контент.
- Для проверки на реальном звуке нарежь свою серию на 5-минутные куски без видео (`samples/` в `.gitignore`); один кусок проходит весь конвейер за ~40 с:

```bash
mkvmerge -q -o samples/chunks_5min/<имя>.mka --no-video -a <русская>,<оригинал> --split duration:00:05:00 <файл.mkv>
```

- Субтитры годятся как подсказка «где речь» для разовых проверок, но конвейер от них не зависит.

## Правила работы

- Поменял поведение, дефолт, ключ конфига или команду — в том же заходе обнови README и этот файл.
- В документацию не записывать частности конкретных файлов (номера дорожек, сдвиги, уровни) как правила — только общие закономерности и инструменты.
- Всё, что проверяется повторяемо, оформлять командой в проекте, а не разовыми вычислениями в чате.
- Разовые прототипы — в scratchpad сессии, не в репозитории.
- Перед удалением/перезаписью посмотреть, что попадёт под удар, и сказать пользователю. `work/` и `out/` пересоздаются конвейером; исходные видеофайлы пользователя не трогать.
- Перед коммитом — `uv run python tools/check_public.py`: в репозиторий не должны попасть пути и имена конкретной машины, названия реальных релизов и студий озвучки, записи.
- Слушать агент не может: при изменениях звука давать объективные цифры (уровни, утечка, срабатывания лимитера) и нарезать фрагменты для пользователя.

## Не реализовано, но спроектировано

**Вход 7.1** (TrueHD/DTS-HD) — редкость, делать когда попадётся. Декодирование 7.1 уже поддерживается, но mix/encode — нет: встроенный eac3-энкодер ffmpeg не умеет 7.1. Нужно сводить в 5.1 самим в Python по ITU: `Ls' = Ls + 0,707·Lrs`, `Rs' = Rs + 0,707·Rrs`, затем контроль клиппинга. Автодаунмиксу ffmpeg не доверять. Atmos-объекты при декодировании теряются (TrueHD Atmos и DTS:X → 7.1-bed, E-AC3 JOC → 5.1-core) — это принято.

**Русская 5.1 как источник голоса.** Сейчас русская дорожка всегда сводится в стерео перед вычитанием. Если пользователь выберет многоканальную озвучку, это работает, но не оптимально (голос можно брать из её центра).

**Дубляж 2.0.** Английская речь в C удаляется вычитанием, а не берётся «инструментальный» выход сепаратора: `C = C − alpha·C_dialog_en + gain·ru_voice`, `alpha ≤ 1` и снижается там, где громкие эффекты перекрываются с речью — тогда ошибки сепаратора звучат как недоудалённый голос, а не как дыры в эффектах. `C_dialog_en` — сепаратор dialog/rest по C (чанки 30-60 с с кроссфейдом); L/R обрабатывать только если в них найдена значимая речь. Русский голос: сепаратор по русской стереодорожке, затем эталонное вычитание песен и вокала M&E (они совпадают с оригиналом). `gain` пофразово: RMS русской фразы согласовать с RMS английской речи в том же отрезке. Реверберация английской речи в тылах частично остаётся — это приемлемо.

**Автоопределение режима.** Когерентность русской дорожки с даунмиксом оригинала на участках английской речи: высокая — закадр (английская речь слышна под голосом), низкая — дубляж. Плюс ручное задание в конфиге.

**Сепараторы — сравнить перед выбором** на фрагментах (тихий диалог, экшен, музыка с речью, шёпот, крик): вокальные MelBand RoFormer (Kim), BS-RoFormer (viperx); кино-сепараторы dialog/music/effects на DnR (BandIt, DnR v3 от MVSep). Инструменты: ZFTurbo Music-Source-Separation-Training или python-audio-separator; PyTorch (GPU, если есть), иначе CPU. Метрики: прослушивание, остатки английского (faster-whisper language-ID, CPU int8), энергия эффектов вне речи.

**Контроль качества по сегментам:** остатки английского (для дубляжа), потеря эффектов вне речи по полосам, скачки громкости между фразами; проблемные сегменты переобрабатывать с другими параметрами, нерешённые — в HTML-отчёт с таймкодами.

**Чего не делать:** не «улучшать» русскую запись (AI-апскейл, расширение полосы) — качество голоса ограничено исходником. Без облачных API.
