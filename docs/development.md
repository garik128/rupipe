# Разработка

Правила работы для людей и ИИ-агентов — в [AGENTS.md](../AGENTS.md). Здесь — как устроены шаги, что лежит в рабочей папке, тесты, сборка скилла и проверка перед публикацией.

## Настройки

Порядок загрузки: `config.yaml` (общие умолчания, с комментариями к каждому ключу) → `config.local.yaml` рядом с ним, если есть (настройки конкретной машины: пути к программам, рабочие папки; в репозиторий не попадает) → файл из `--config` (разовые переопределения). Каждый следующий меняет только те ключи, которые в нём есть.

`tools.*` — полный путь к программе или её имя для поиска в PATH. Пустые `work_dir`, `output_dir`, `fragments.dir` означают `rupipe-out` рядом со входом; `--out <папка>` переопределяет все три.

## Что лежит в рабочей папке

`<work_dir>/<имя файла без расширения>/`:

| файл | что это |
|------|---------|
| `manifest.json` | готовые шаги и их результаты |
| `pipeline.log` | лог |
| `orig_<канал>.wav` | оригинал, float32 48 кГц, по файлу на канал (`FL FR FC LFE SL SR` для 5.1(side)) |
| `ru_FL.wav`, `ru_FR.wav` | русская дорожка как есть |
| `ru_aligned_FL.wav`, `ru_aligned_FR.wav` | русская дорожка, сдвинутая под оригинал |
| `voice_raw.wav` | выделенный голос (моно), до гейта |
| `voice_C.wav` | голос после гейта, в масштабе центрального канала |
| `vad.npy` | где звучит русский голос (по кадрам STFT) |
| `mix_<вариант>_<канал>.wav` | изменённые каналы варианта |
| `ru51_<вариант>.eac3` | закодированная дорожка варианта |

Объём: порядка 8 ГБ на час 5.1.

## Как работают шаги

**analyze.** ffprobe даёт список дорожек. Dialnorm ffprobe не показывает: он читается из заголовка первого кадра AC3/E-AC3. Оригинал без явного выбора — дорожка с наибольшим числом каналов, если среди таких ровно одна не помечена русской; русская без явного выбора — только если кроме оригинала в файле одна дорожка. Иначе нужен выбор. Если выбор изменился, файл обрабатывается заново с начала.

**decode.** ffmpeg с `-drc_scale 0`: иначе декодер AC3/E-AC3 сжимает динамику. Русская дорожка всегда сводится в стерео.

**sync.** Начальное смещение — из `start_time` дорожек в контейнере. Затем GCC-PHAT (полоса 100-8000 Гц) между даунмиксом оригинала и русской дорожкой в окнах `window_s` через каждые `step_s` по всему файлу. Тихие окна и окна с неуверенным пиком (`min_confidence`) отбрасываются. Соседние окна, согласные в пределах `run_tolerance_samples`, образуют кусок с одним сдвигом; одиночное окно, не согласное с одинаковыми соседями, считается ошибкой замера. Границу между кусками ищут короткие окна (`refine_*`). Каждый кусок сдвигается на свой дробный сдвиг (интерполяция windowed-sinc), на стыках кроссфейд `crossfade_ms`. Русские дорожки веб-релизов бывают склеены из кусков с разными сдвигами; ошибка даже в несколько сэмплов ломает вычитание на верхах, поэтому сдвиг меряется по всему файлу. Больше `max_segments` различных сдвигов — файл помечается `flagged` (похоже на плавный дрейф). Различными считаются сдвиги, отличающиеся от первого сдвига группы больше чем на `flag_tolerance_samples` (`distinct_offsets` в результате шага): замеры одного и того же сдвига бывают разбросаны на сэмпл-другой от окна к окну, и на длинном файле это давало десяток «кусков» без настоящего дрейфа. Подбор сдвигов и сшивка кусков от этого параметра не зависят. Знак: `lag = L` значит, что русский сэмпл `j` звучит вместе с сэмплом оригинала `j + L`.

**voice.** Русская дорожка моделируется как `g(t, полоса) · H(f) · оригинал + голос`. `H` — комплексная матрица даунмикса студии (каналы оригинала без LFE → L, R), подбирается МНК по всему файлу; заодно учитывает дробную часть смещения. `g` — медленно меняющееся усиление студии по 14 полосам. Остаток после вычитания — голос плюс шум кодека; уровень этой утечки оценивается по полосам (`leak_percentile`) и подавляется спектральной маской (`oversubtract`, `mask_floor_db`). Затем VAD по выделенному голосу, гейт между фразами (`gate_*`), измерение глубины студийного приглушения и пересчёт голоса в масштаб центра: голос делится на коэффициент, с которым FC оригинала вошёл в L/R русской дорожки. Так сохраняется баланс голос/оригинал, выбранный студией.

**mix.** Берёт до 400 случайных секунд русской речи и считает их спектры (голос, центр, остальные каналы) — `audibility.py`. Для каждого варианта: `FC = duck(t) · FC + 10^(voice_db/20) · голос`, где `voice_db: auto` — самый тихий уровень (шаг 0,25 дБ, в пределах `voice_db_min`/`voice_db_max`), при котором доля слышимых клеток речи достигает `target_audible`; в manifest и лог пишутся достигнутая разборчивость, она же у студии и голос над центром в дБ. Каналы из `duck_channels` приглушаются под голосом (`duck_db`, атака/спад `duck_attack_ms`/`duck_release_ms`). Лимитер срабатывает только на пиках выше `ceiling_dbfs`; число затронутых сэмплов пишется в manifest.

**encode.** ffmpeg, `eac3`, `export.bitrate` (1024k), dialnorm как у оригинала, раскладка как у оригинала.

**mux.** mkvmerge: видеодорожки, затем новые дорожки, затем все остальные исходные в прежнем порядке. Записывает в manifest, под каким номером каждая исходная дорожка оказалась в готовом файле (`track_map`): дальше дорожки находятся по нему, а не по тегам языка.

**fragments** (отдельная команда). По оригиналу и VAD считает посекундно громкость, LFE, пики, долю речи и соотношение фронт/тылы к центру и выбирает до 4 непересекающихся сцен: `talk`, `boom`, `music_talk`, `quiet_talk`. Режет их mkvmerge из готового файла (видео, новые дорожки, оригинал, исходная русская, субтитры) и дописывает описание в `<имя>.fragments.txt`.

## Тесты

```bash
uv run pytest
```

Тесты синтетические: записей в репозитории нет. Для проверки на реальном звуке нарежьте свою серию на 5-минутные куски без видео в `samples/` (папка исключена из репозитория), см. AGENTS.md.

## Видеопробы после mix

Отдельный инструмент для новых материалов и проверки синхронизации на телевизоре/саундбаре:

```bash
uv run python tools/video_previews.py "<рабочая папка файла>" --source "<исходный MKV>" --config "<конфиг вариантов>" --out samples/listen/video-trial --at 600 --at 1800 --length 90 --default main
```

`--at` задаёт секунды исходника и повторяется для нескольких сцен; `--length` — желаемая длительность (по умолчанию 90 секунд), `--default` — имя предпочтительного варианта микса. Выходная папка должна быть новой. Команда проверяет соответствие источника манифесту, копирует видео через mkvmerge с ближайшего следующего ключевого кадра и режет звук с точно той же позиции. Длительность корректируется по фактически вырезанному видео: начало и конец округляются к ключевым кадрам. Добавляются варианты E-AC3 5.1 с исходным dialnorm и битрейтом из конфига. Пробы содержат видео и новые аудиодорожки; исходные озвучки и субтитры в них не включаются. Видео не перекодируется; проверяются хеш первого видеопакета, нулевые начала дорожек, параметры HDR и длительность. Пока требуется нулевой `start_time` оригинального звука. Зритель оценивает синхронизацию на слух и по картинке. Команда не включена автоматически в обычную сборку сезонов.

## Аудиопроба без полного MKV

После `pipeline run ... --until mix` можно собрать короткие пробы, не копируя большое видео:

```bash
uv run python tools/preview_mix.py "<рабочая папка файла>" --config "<конфиг вариантов>" --out samples/listen/audio-trial --count 4 --length 60
```

Выходная папка должна быть новой. Команда выбирает сцены по существующим метрикам `scenes.py` и добавляет пробы вокруг неперекрывающихся границ синхронизации. Для каждой сцены создаёт стерео WAV каждого варианта, оригинала и синхронизированной исходной русской дорожки, а также MKA с E-AC3 5.1 всех вариантов и оригинала. Оригинал в пробе повторно закодирован, Atmos не сохраняется. Сейчас поддерживается только 5.1(side) с изменённым центром. Раскладка кодирования задаётся явно, битрейт берётся из конфига, dialnorm — из оригинала. WAV используют одинаковое ослабление для всех версий одной сцены, чтобы избежать клиппинга; LFE в стерео не подмешивается. Цель разборчивости 5.1 не калибровать по стереопробе без проверки на основной системе. Проверяются полные длины исходных каналов и длина/кодек/канальность проб. Видео в пробах отсутствует; полный mux выполняется после прослушивания.

## Дочистка голоса BandIt Plus

`tools/compare_bandit.py` сравнивает `voice_C.wav` до и после нейросетевой очистки на коротких отрывках. Основные файлы, манифест и настройки микса не меняются. Требуется отдельное окружение с PyTorch, torchaudio, numpy, scipy, soundfile, tqdm, librosa, spafe и pytorch_lightning, а также внешний код инференса [bandit-Wolfram](https://github.com/wolfram0108/bandit-Wolfram). Проверенная реализация: коммит `f79c76e053cee073b74642ff5c881d95374fb16b`. Скрипт импортирует построение модели, но использует собственный CPU-инференс без CUDA-вызовов.

Используется `model_bandit_plus_dnr_sdr_11.47.ckpt`, SHA-256 `c48284779f7d1258a6527d3aaa18a532d45c1f506e2dcc25d5ab179a8c5e2573`. Веса загружаются с `weights_only=True` и строгой проверкой всех ключей. Пример запуска из отдельного окружения:

```bash
python tools/compare_bandit.py "<рабочая папка файла>" --upstream "<папка bandit-Wolfram>" --checkpoint "<файл весов>" --sha256 c48284779f7d1258a6527d3aaa18a532d45c1f506e2dcc25d5ab179a8c5e2573 --out samples/listen/bandit-trial --at 600 --at 1800 --length 30
```

Папка результата должна быть новой. Инференс выполняется при 44,1 кГц с возвращением в 48 кГц, чанками по 6 секунд с перекрытием 2 секунды; для отрывка используется дополнительный контекст по краям. WAV до/после и удалённый остаток имеют один общий коэффициент громкости. Несжатый float-результат сохраняется отдельно для последующего тестового микса. `report.json` содержит версии, хеш весов, коммит реализации, длительности, лаг и интервалы падения энергии более чем на 12 дБ в предполагаемой речи. Эти интервалы — кандидаты для прослушивания, а не доказанные пропуски слов. Дочистку не добавлять в рабочий микс до оценки пользователя; фон оригинальных каналов нейросетью не обрабатывать.

Для подбора сложных сцен есть `python tools/select_voice_trials.py "<рабочая папка>" --out work/voice-trials.json`: выбираются 30-секундные речевые кандидаты с громким окружением и сильным остатком в паузах, исключаются последние 10% фильма. Это энергетическая эвристика; содержание и остатки проверяются прослушиванием.

Тот же инструмент сравнения поддерживает TIGER-DnR: добавьте `--engine tiger --model-config <config.json> --device xpu --chunk 12 --overlap 8`, передав код [TIGER](https://github.com/JusperLee/TIGER) в `--upstream` и официальные safetensors из [JusperLee/TIGER-DnR](https://huggingface.co/JusperLee/TIGER-DnR) в `--checkpoint`. Проверенная ревизия весов `b7a5956`, SHA-256 `dd1c696e72f6adea0085ef1af640882a8260519ad666422835e387a5b4abdd2a`; код `9f18d4a10a7137e1ce8052cfb62215179f1287b6`. В отдельном XPU-окружении нужны PyTorch/torchaudio XPU, safetensors, huggingface-hub, numpy, scipy, soundfile, librosa, torch-complex, typeguard 2.x, pytorch-lightning 2.0.2 и rich. Запускается только диалоговый компонент с выходом 2, как в штатном `TIGERDNR.forward`; веса всего набора проверяются строго. `--device cpu` задаётся явно, если XPU недоступен. В отчёт включается пиковая выделенная память GPU. Дополнительный WAV исходной русской дорожки нужен для проверки содержания сцены и имеет собственное ослабление от клиппинга; пара до/после по-прежнему использует одну общую громкость.

### Контекст для сравнения дочистки

Если переключать дорожки неудобно: `python tools/split_trial_tracks.py <папка проб> --pattern "*_context.mkv" --out <новая папка>`. Для каждой сцены создаётся подпапка с отдельным MKV для каждой аудиодорожки. Видео и звук копируются без перекодирования, в каждом файле ровно одна дорожка по умолчанию. Исходные пробы сохраняются; выходная папка должна быть новой. Проверяются число дорожек, кодек, канальность и длительность.

```bash
python tools/clean_voice_video_trials.py "<рабочая папка>" --clean "<папка сравнения TIGER>" --source "<исходный MKV>" --config "<конфиг вариантов>" --variant moderate --out samples/listen/tiger-context
```

Команда использует готовые float-отрывки и не запускает нейросеть. Выходная папка должна быть новой. В MKV помещаются исходная русская стереодорожка (по умолчанию), миксы с выбранным уровнем до/после TIGER и английский оригинал. Исходные дорожки и видео копируются без перекодирования. Начало выбирается около измеренного появления голоса с сохранением ключевого кадра; возможен короткий запас до речи. Отрывки ограничены длиной уже очищенного звука. Дочищенный голос добавляется только в FC; остальные каналы берутся из того же оригинала. Проверяются источник, длина, первый видеопакет и количество дорожек. Нужен исходный 5.1(side) со стартом оригинала в нуле; выбранный вариант должен менять только FC.

## Сравнение VAD

`tools/compare_vad.py` сравнивает наш VAD с Silero на результате `run ... --until voice`. На прослушивании Silero приглушал настоящие фразы даже при пороге 0,2; инструмент сохранён для экспериментов, основной детектор не меняется.

```bash
uv pip install --target work/vad-deps --no-deps silero-vad==6.2.3 onnxruntime==1.31.0 flatbuffers==25.12.19 protobuf==7.36.2 packaging==26.3
uv run python tools/compare_vad.py "<рабочая папка файла>" --deps work/vad-deps --model work/vad-deps/silero_vad/data/silero_vad.onnx --out samples/listen/vad-test
```

Выходная папка должна быть новой. `--config` задаёт тот же конфиг, что использовался при выделении голоса; `--threshold` меняет чувствительность Silero (по умолчанию 0,5); `--clips-from <предыдущая папка>/report.json` сохраняет позиции отрывков. Выход: полные FLAC, короткие WAV, маски и отчёт. Выделение, масштаб, громкость и параметры гейта одинаковы, отличается только маска речи; даккинг и автоматическая громкость микса не пересчитываются. Расхождение масок не является точностью: слова и фон проверяются на слух. Приглушение пауз не очищает фон внутри фраз.

## Скилл для ИИ-агентов

```bash
uv run python tools/build_skill.py
```

Исходники — `skill/` (`SKILL.md` и справочники на английском: их надёжнее понимают любые модели; `README.ru.md` — для человека). Сборщик копирует туда код `rupipe/` и `config.yaml`, проверяет правила формата Agent Skills (agentskills.io) и то же, что `check_public.py`, и пишет `dist/russian-voiceover-51/` и `dist/russian-voiceover-51.zip`. После правок кода или поведения — обновить `skill/` и пересобрать.

## Перед публикацией

```bash
uv run python tools/check_public.py
```

Проверяет все файлы, которые попадут в git (с учётом `.gitignore`): нет адресов почты (кроме служебных), IP-адресов, путей к папкам пользователей, медиафайлов, больших файлов, управляющих символов; личные файлы (`*.local.*`) не попадают в коммит. Слова, которые нельзя публиковать (имена, пути и сеть своей машины, названия реальных релизов и студий), каждый держит в своём `tools/forbidden-words.local.txt` — по одному на строку; сам этот список не публикуется, иначе он бы их и раскрыл.
